具身智能实验室调研与阶段1执行计划（2025-至今）
 设备现状与目标
现有设备：
1. 双足人形机器人两台  
2. 单下肢双足机器人一台  
3. 四足机械狗一台  
4. Franka 7自由度机械臂一台
目标：搭建一个可持续产出“场景展示 + 控制策略研究 + 论文成果”的具身智能实验室。
arXiv 论文调研（2025-至今，按设备映射）
 A. 双足/人形机器人
趋势：统一全身控制（loco-manipulation）、遥操作示教、长时任务鲁棒性。
- HWC-Loco (arXiv:2503.00923)
  分层全身控制，强调安全恢复与任务完成平衡。
- A Unified and General Humanoid Whole-Body Controller / HUGWBC (arXiv:2502.03206)
  单策略支持多步态，且支持上身外部干预。
- ULC (arXiv:2507.06905)
  统一细粒度全身控制，兼顾跟踪精度、鲁棒性与大工作空间。
- TWIST (arXiv:2505.02833)
  全身遥操作与动作模仿，单网络覆盖多技能。
- CLONE (arXiv:2506.08931)
  闭环误差校正，降低长时遥操作漂移。
 B. 单下肢双足机器人
趋势：欠驱场景下的稳定性控制、约束强化学习、MPC与RL融合。
- Constrained Reinforcement Learning for Unstable Point-Feet Biped (arXiv:2508.02194)
  约束终止 + 随机化，提升欠驱双足 sim2real 稳定性。
- LIPM-Guided RL for Bipedal Locomotion (arXiv:2509.09106)
  引入 LIPM 先验提升动态平衡与感知稳定。
- RL-augmented Adaptive MPC for Biped (arXiv:2509.18466)
  MPC+RL 混合范式，增强复杂地形适应。
 C. 四足机械狗
趋势：VLA（视觉-语言-动作）与长时移动操作一体化。
- MoRE (arXiv:2503.08007)
  面向四足 VLA 的混合专家与 RL 微调框架。
- ODYSSEY (arXiv:2508.08240)
  长时任务分解 + 全身移动操作策略 + sim2real。
- MobileVLA-R1 (arXiv:2511.17889)
  强化推理一致性和连续控制稳定性。
 D. Franka 7-DoF 机械臂
趋势：扩散策略、跨末端执行器泛化、3D一致动作表示。
- Pick-and-place Manipulation Across Grippers Without Retraining (arXiv:2502.15613)
  不重训跨夹爪迁移，实用性强。
- Kinematics-Aware Diffusion Policy (arXiv:2512.17568)
  3D节点动作表示 + 运动学约束，强调泛化与可执行性。
- Can Context Bridge the Reality Gap? (arXiv:2511.04249)
  上下文感知策略改善 sim2real 表现。

 场景推荐（兼顾展示与研究）
 S1 包裹搬运接力（优先）
流程：四足巡检定位 -> 人形搬运绕障 -> Franka 分拣上架。  
价值：展示性强，可研究跨形态协同与故障重规划。
 S2 人形全身遥操作到自主策略蒸馏
先遥操作采集高质量数据，再蒸馏为自主策略。  
价值：可形成“数据-策略-部署”闭环。
 S3 单下肢双足极限稳态赛道
斜坡、低摩擦、碎石、推扰等场景。  
价值：适合控制策略论文，指标清晰（恢复时间、跌倒率、能耗）。
 S4 Franka 跨夹具泛化操作站
同任务跨夹具运行（尽量零重训）。  
价值：贴近工业痛点，工程复用度高。
 S5 四足语义巡检与事件处置
自然语言任务下发 -> 四足巡检 -> 人形/机械臂处置。  
价值：体现“具身智能代理”能力。
 阶段1实验室建设蓝图 v2（1-2个月）
本阶段定位：完成实验室级基础能力建设（Lab Readiness），让后续项目可以并行实施，而不是每个项目重复搭底座。
阶段1总目标：
1. 完成“空间 + 硬件 + 软件 + 数据 + 流程 + 组织”六层基础设施  
2. 四类设备全部具备最小可复现实验与统一接入能力  
3. 建立统一系统流水线：感知 -> 规划 -> 技能调用 -> 安全监控 -> 告警与接管 -> 复盘
 分层架构与建设范围
 L1 空间与设施层（实验室物理基础）
- 功能分区：动态运动区、机械臂操作区、调试区、观摩区、充电与备件区
- 安全边界：软硬隔离、急停布局、禁入区域、可视化警示
- 基础设施：独立供电回路、UPS、网络布线、时钟源设备、照明与地面标定
- 运行动线：设备出入场、人员行走、测试路线、应急疏散
 L2 硬件与运维层（设备可用性基础）
- 设备台账：序列号、固件版本、维护记录、责任人
- 标定体系：相机外参、IMU、力传感器、机械臂TCP、底盘里程计
- 备件体系：电池、线缆、易损件、夹爪指尖、固定治具
- 维护制度：日检、周检、月检与故障工单流程
 L3 软件栈与中间件层（可集成基础）
- 版本矩阵：OS/驱动/ROS2/仿真器/控制框架统一基线
- 中间件规范：命名空间、Topic/Service/Action命名、QoS与频率
- 配置管理：环境变量、参数模板、设备配置文件统一管理
- 发布策略：开发/测试/生产环境区分，支持回滚
 L4 数据与实验基础层（可复现基础）
- 时间同步：PTP优先，Chrony/NTP备选，统一时钟监控
- 日志标准：原始数据、状态、控制、告警、接管、版本信息全量留痕
- 实验主键：统一 `run_id`，全链路追踪“代码版本 -> 参数 -> 模型 -> 结果”
- 回放系统：按时间轴重放并支持模块对齐分析
 L5 系统流水线层（可运行基础）
- 统一流水线：`PerceptionOutput -> PlanOutput -> SkillCommand -> SafetyState`
- 安全闭环：速度限制、区域限制、碰撞预测、急停、人工接管
- 任务调度：任务状态机、超时策略、失败重试、降级路径
- 监控告警：延迟、频率、丢包、温度、电量、CPU/GPU占用
 L6 组织与流程层（可持续基础）
- 角色职责：系统、算法、基础设施、实验、安全员职责明确
- 变更评审：接口变更、硬件变更、关键参数变更需评审
- 实验流程：申请、执行、复盘、归档、复现实验
- 风险管理：分级预案（一般/严重/停机级）与演练制度
 WBS任务分解（可执行清单）
 WBS-A 空间与安全
- 完成平面布局图和安全分区图
- 部署急停链路和电子围栏
- 完成网络、供电、摄像监控与门禁规划
- 形成《实验室安全SOP v1》
 WBS-B 硬件接入与运维
- 完成四类设备接入清单与驱动自检脚本
- 完成标定工具链和标定记录模板
- 建立备件库存最小阈值
- 形成《设备点检与维护手册 v1》
 WBS-C 软件与中间件基线
- 冻结版本矩阵（含升级与回滚策略）
- 发布统一消息接口定义与参数字典
- 建立配置仓库与启动脚本模板
- 打通CI基础检查（接口兼容、参数完整性）
 WBS-D 数据与回放底座
- 打通时间同步与偏差监控
- 建立统一日志采集、索引、检索、归档
- 上线回放工具（支持跨模块时间对齐）
- 形成《实验数据治理规范 v1》
 WBS-E 流水线与最小闭环
- 跑通统一流水线和安全链路
- 每台设备完成1个最小可复现实验
- 打通sim2real最小链路（每台至少1条）
- 输出Benchmark v1（成功率、时延、接管率等）
 WBS-F 组织与交付
- 建立RACI职责表和例会节奏
- 建立变更评审机制（每周一次）
- 完成培训与新成员入场流程
- 封版阶段1资产包（文档、脚本、配置、报告）
  里程碑（周粒度）
 第1-2周：蓝图冻结与基础设施启动
- 冻结实验室平面、安全边界、网络供电方案
- 冻结软件栈版本矩阵和接口v1
- 建立设备台账、点检模板、run_id规范
- 输出：`架构蓝图 v1`、`接口规范 v1`、`安全SOP v1`
 第3-4周：基础能力打通
- 完成时钟同步、日志采集、回放工具首版
- 完成四类设备驱动自检与健康监控
- 跑通统一流水线（单机模式）与安全链路
- 输出：`数据治理规范 v1`、`回放工具 v1`
 第5-6周：最小闭环与sim2real
- 每台设备完成最小任务并固定参数模板
- 每台设备至少1条sim2real闭环跑通
- 建立“模型-参数-结果”追踪与自动报表
- 输出：`设备最小任务报告`、`sim2real报告`
 第7-8周：联调封版与交接就绪
- 完成双设备联调（建议四足+人形）并接入Franka协同
- 完成异常处理演练（急停/网络中断/控制超时）
- 形成阶段1封版资产和Go/No-Go评审
- 输出：`阶段1封版包`、`Benchmark v1`
 RACI职责矩阵（建议）
- 系统负责人（A）：总体方案、里程碑、Go/No-Go审批
- 基础设施工程师（R）：网络供电、时钟、日志、回放、监控
- 控制/算法工程师（R）：最小任务、sim2real、参数模板
- 实验工程师（R）：现场执行、安全检查、数据质检
- 安全员（C）：风险评估、应急演练、事故复盘
- 项目管理/助理（C）：台账、工单、会议纪要、版本记录
说明：`A` 负责最终签字，`R` 负责执行，`C` 参与评审与建议。
 Go/No-Go 验收清单（阶段1出关门槛）
 设施与安全（必须通过）
- 功能分区、急停链路、禁入区、应急预案全部可用
- 至少完成2次应急演练并留档
 软件与中间件（必须通过）
- 版本矩阵冻结并可一键部署
- 接口规范v1冻结，变更流程生效
 数据与复现（必须通过）
- 任意实验可按 `run_id` 完整追溯
- 回放工具可重现一次失败案例并定位问题模块
 设备能力（必须通过）
- 四类设备各1个最小任务重复10次成功率达标
- 四类设备各至少1条sim2real闭环可复现
 组织流程（必须通过）
- RACI、SOP、变更评审、周会机制正式运行
- 新成员按文档可独立完成一次标准实验
 Day 1-3 启动动作（立即执行）
1. 召开阶段1启动会，冻结六层建设范围与里程碑  
2. 输出实验室平面图、安全分区图、网络拓扑草案  
3. 冻结版本矩阵、接口v1草案、run_id与目录规范  
4. 明确RACI负责人，建立周例会与变更评审机制
 阶段1完成标志（升级版里程碑）
- 实验室达到“项目可并行启动”状态，而非单项目可演示状态  
- 空间、安全、设备、软件、数据、流程六层基础均已封版  
- 四类设备全部具备最小可复现实验和sim2real最小链路
