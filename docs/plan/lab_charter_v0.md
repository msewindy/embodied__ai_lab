## 0. 一句话

**本实验室要建的是：一次具身行动既能被「算数」，又能在可计算的物理世界上下文中被理解与执行。**

三层叠放、不揉并：

- **L0 Lab OS**：实验如何合法跑完、留下证据。  
- **L1 Strategy Runtime**：机器人如何理解并作用于物理世界——**重心是中层时空上下文，不是某一个网络。**  
- **L2 Task Pack + Low 桥**：这一题怎么摆、怎么同构地接到仿真/真机。

世界模型不是与平台平行的第二套大框架，而是 L1 的推荐组织方式：**先决定此刻什么算世界状态（情境化选择），再可选地预见若这样动世界如何变。**  
学习算法（含 LeRobot）是挂在该上下文上的插件，不是内核。

## 1. 我们从哪来（架构调整史 · 读宪章必读）

宪章不是从开源调研凭空写出来的。没有这条历史，就会把平台理解成「带 `run_id` 的 LeRobot」，或把世界模型理解成「再训一个预测头」。

| 阶段 | 当时的问题 | 调整 |
|------|------------|------|
| **建设总纲 / Walking Skeleton** | 要先有实验室操作系统：场地、安全、RunManager、ROS 契约 | 根上的 L0 总体方案；工程主路径一度偏 **Go2** |
| **战略锚点冲突** | 业务 Pilot 在臂（Franka），验收本体却在腿 | 必须换锚点，否则平台托举的是错负载 |
| **两套「框架」并存** | 仓库内 Lab OS 自称框架；仓外世界模型三层（High/Mid/Low）也自称框架 | [FUSION](./platform_wm_fusion_plan_v0.md)：**叠放，不揉并**。平台管算数，三层控制作为第一个 Agent Runtime 接入 |
| **成功标准分离** | 怕用 H1–H5 或跨夹具 KPI 当框架 Go | 平台 Go ≠ 研究 Go ≠ Pilot Go |
| **CTRL-SIM 同构** | ws-02「禁止 ROS2」与真机验证矛盾 | 仿真 **DOMAIN 43** 与真机 **42** 同消息、禁混域；批处理仍可无 ROS |
| **STRUCT 三层落点** | 「平台 vs 场景脚本」不够；情境/技能被私造 | 明确 **L0×L1×L2**；L1 = Strategy Runtime；世界模型 = L1 的组织形态 |
| **Phase-1 收口** | 要证明叠放能跑 | M2–M6：Low 桥、run、A/B 轨、薄 Mid、Scene 抓放、E2E PASS（2026-08-07） |
| **L1 代码出壳** | Mid 堆在 `ctrl_sim` 会污染 Lab OS | L1 → 本仓 `strategy_runtime/`；`external/world_model` 只挂设计 |
| **真机暂停、加深 L1** | 再铺真机解决不了「Runtime 仍是脚本袋」 | 仿真上把 L1 做成运行时，而不是先拆文件夹、先上 ACT |
| **开源全量调研** | 怕 L1 无母本、或误 fork 学习库 | 开源强在学与 Env，**弱在时空上下文运行时**；LeRobot = 数据契约 + 算法插件 |
| **本宪章 v1.0 的偏差** | 写成「能算数 + 别做成 LeRobot」 | **v1.1 纠正**：L0 必要但不是灵魂；灵魂在 L1 的**时空上下文 / 中层** |

因此：L0 已经相对成形；当前与往后的主战场是 **把 STRUCT §3 的世界上下文做成可替换运行时**，而不是把平台做成学习库外壳。

## 2. 要解决的根本问题（三问，缺一不可）

### 2.1 实验怎么算数？（L0）

谁开的跑、用哪套场景与软件钉扎、数据能否复现、结论能否进 Index。  
没有这一层，研究对照无法审计，安全与多用户无法落地。

### 2.2 机器人如何理解并改变物理世界？（L1 · **本实验室差异化所在**）

人类有意识地改变世界，不是「图像进、关节出」一条映射，而是多层闭环：

- **高层（薄、可缺省）**：目标、子目标、失败时重规划；不发关节指令。  
- **中层（厚、必选）**：在时空上下文中选择**此刻什么算状态**，调用技能，短时程监控；可选前向预见。  
- **低层（契约化、现成伺服）**：把任务空间意图变成受安全约束的运动，并回传可过期的状态。

中层要回答两件开源几乎不当运行时一等公民的事：

| 记号 | 问题 | 不是 |
|------|------|------|
| **WM-B** 情境化状态选择 | 现在什么算世界状态？该让哪些信号进入闭环？（兴趣感知 / 门控 / 对象与关系） | 把所有像素和关节一股脑塞进网络 |
| **WM-A** 动力学预见（可选） | 若执行这段动作，世界变成什么样？ | 第一期就必须上视频大模型 |

纯端到端 \(\pi(a\mid o)\) 把「该看什么」与「该怎么动」捆死，用数据覆盖率硬扛情境变化——**结构上低效**。本实验室主张策略宜靠近 \(\pi(a\mid s, g)\)：先有可计算的 \(s\)（上下文投影），再行动。  
VLA/ACT 可以是后端之一；**它们替代不了中层上下文服务。**

理论展开在仓外：`external/world_model/docs/人类交互与具身智能控制路线分析.md`（§2.6–2.7）、`通用具身核心能力与中层验证讨论纪要.md`。本宪章只钉**实验室必须承认这些能力存在，并给它们层与接口**，不把 H1–H5 写成框架 Go。

### 2.3 这一题如何版本化而不污染 Runtime？（L2）

桌面几何、杯碗格点、相机外参、这句任务语言、这个 checkpoint——属于 Task Pack。  
换题不应改 Lab OS，也不应把 Runtime 写成「红杯脚本」。

## 3. 三层叠放（均衡职责）

```text
L0  Lab OS          门禁 · run_id · 锁 · 录制/导出 · Index · DOMAIN
        │  编排，注入 run_context
        ▼
L1  Strategy Runtime
        High（薄）
        Mid（厚）：World Context · 技能 · 谓词 · 主控制环
        PolicyBackend ∈ {template, oracle, lerobot.*, wm.*}
        │  MidGoal / SkillIntent / 上下文查询
        ▼
L2  Task Pack + Low 桥
        scene.yaml · USD · profile
        franka_sim_bridge / 真机桥   WorldBackend ∈ {isaac_sim, franka_real}
```

| 层 | 负责 | 禁止 |
|----|------|------|
| **L0** | 谁能开跑；资源锁；PreFlight；`run_id`；A/B 轨权威路径；Index；安全策略入口 | 实现抓取策略、情境推理、前向世界模型、场景几何算法；把训练循环塞进 RunManager |
| **L1** | 世界上下文服务；MidGoal 调度；技能步进；成功/失败/HOLD；从上下文**投影**出策略观测；可插拔后端 | 绕过 `run_id` 写主结论；直改急停硬件；把某一 Task 写死进核心；自研总线替代 ROS；把仿真 `Env.step` 搬进 Runtime |
| **L2** | 场景资产与 pin；任务语言；`action_schema` / fps / cameras；profile 剧本；桥接仿真或真机 | 第二套归档规范；私改 DOMAIN；绕过 TECH-02 |

两类共性不要混层：**实验共性 → L0**；**具身/策略共性（上下文、技能、谓词）→ L1**；**任务特异 → L2**。

WorldBackend（Isaac / 真机）属于 **L2-Low**，不是 L1。L1 不拥有物理步进；它读状态与物体，写意图。

## 4. L1 的核心：时空上下文（World Context）

L1 的核心**不是** ACT，也**不是**「再包一层 `select_action`」。  
核心是对策略与技能可查询的**物理世界接口**。

```text
World Context
├── State s          关节 / ee / 接触 / 安全 / run 元数据          ← 现有 LowState
├── Objects          位姿、类别、关系（Oracle → 感知 → 学习槽位）   ← 现为 YAML 名义位姿
├── Constraints      工作空间、软限、可供性提示
├── Goals / Predicates  要达成的状态（cup_in_bowl …）ε 来自 L2
├── Skill I/O        MidGoal ↔ SkillIntent / gripper
├── Memory（可选）    跨步失败原因、关系；不阻塞第一期
└── Forward（可选）   WM-A：若动作 a，s 如何变；不阻塞第一期
```

**组织原则：**

1. **上下文先于策略。** 模板、Oracle、学习策略、未来 `world_model_*` 都消费同一查询面，再各自投影。  
2. **WM-B 先于 WM-A。** 先稳定「什么算 s」（状态选择 / 兴趣门控的挂钩），再谈预测头。缺 B 的「世界模型」只是在过完备空间里预测一切。  
3. **两面分离。**  
   - **策略面**：可进 B 轨、给网络吃（关节、相机、语言条件…）。  
   - **评测/特权面**：物体 GT、谓词几何、Oracle——默认不当训练特征，避免「偷看答案」。  
4. **投影配置。** `PolicyObs` 是从 Context 切出的视图（state-only 是一种配置），不是 MLP 专用 8 维结构体。历史窗属于投影配置，不是每个后端私建 deque。  
5. **术语。** 仓外/LeRobot 说的 World Model 常指网络预测头；本文「世界上下文 / 世界模型运行时」指 **L1 中层服务**。二者可叠加，不可混名。

**诚实（不得写成已实现）：** 今日 Context ≈ `SceneTargets` + 静态 PoseStamped + `LowState`。评测是运动代理，不是 Isaac 物体 GT。静态 YAML **不得自称世界模型**。宪章要求的是把上述槽位做成**可替换服务面**，Oracle 为第一实现，感知与学习 WM 后挂。

## 5. High · Mid · Low（功能同构，实现异构）

仿人类的**功能分层与预测闭环**，不仿生物细节。

| 层 | 时间尺度（量级） | 放什么 | 不放什么 |
|----|------------------|--------|----------|
| **High** | 慢、可间歇、可缺省 | 意图、子目标序列、冲突仲裁、失败重规划 | 关节角、精细几何维护 |
| **Mid** | 持续 | 上下文组装与门控挂钩、技能库、朝目标有界步进、谓词、与 Backend 仲裁 | 某一场景的硬编码 prim；第二套实验 OS |
| **Low** | 控制频率 | 限幅、expire、HOLD、关节伺服；回传 LowState | 任务成败语义、物体槽位 |

主控制环在 **Mid**：同一调度器消费 template / oracle / 学习后端，输出 `SkillIntent`。  
人只记一个正式入口：`lab ctrl-sim run`（profile 选 backend）。  
断流、超时、推理失败 → **HOLD**（与 TECH-02 `expire` 同族）。学习后端可出 chunk，环内切成 intent；单步 = 长度 1。

研究假说 H1–H5（显式情境是否必要、前向是否增益等）在仓外验证方案中定义，**不是**本宪章的框架验收条目。框架要做的是：让这些假说有可插的 \(s\) 与接口，而不是先证完假说再允许有 Runtime。

## 6. 数据与控制总线（L0/L2 纪律，支撑 L1）

- **同构：** CTRL-SIM DOMAIN 43 与真机 42 同一 `SkillIntent` / `LowStateFeedback`；禁混域。  
- **双轨：** A 轨（`low.jsonl` 等）= 评测与审计主证据；B 轨 = LeRobot Dataset v3 学习入口。manifest **强制互链**；无链接不算正式学习数据。  
- **评测：** 谓词计算在 L1，ε 与目标几何在 L2，是否算进 Index 由 L0 挂载。  
- **口令：** 可以玩（单测）；算数必须走 `lab`。

## 7. 开源与算法以什么身份进入

开源仓覆盖学习栈、仿真 Env、语言条件、数据扩增——**几乎都不提供与本仓对等的时空上下文运行时。** 故：

| 来源 | 身份 |
|------|------|
| LeRobot Dataset v3 / Processor / Policy | **B 轨契约 + 可选 Backend 实现**；`import lerobot` 仅允许出现在适配器内 |
| LeRobot Robot / Env / 以其 CLI 当实验 OS | **不采用** |
| Isaac Lab / ManiSkill / robosuite | 声明式任务元数据可借鉴；**不**把 Env.step 当 L1 |
| 仓内 numpy MLP | **仅** state 路径回归夹具 |
| ACT 等训练 | **仓外**；权重 + processor 登记 Index |

换算法只换 Backend；**不换 Context 服务、不换 Mid 主循环、不换 Low 消息、不换 `run_id`。**

详细适配见 STRUCT §13。本节在宪章中的地位是边界，不是正文重心。

## 8. 我们明确不是什么

| 不是 | 因为 |
|------|------|
| **没有上下文的策略袋** | 只调 `select_action`、各脚本私造 obs，会回到 STRUCT 要消灭的状态 |

| **开源仓 fork / Submodule 进本仓** | 见 `external/README.md` |

## 9. 怎样算框架做成了

做成，当且仅当同时趋向：

1. **上下文可查询、可替换：** 策略与技能不 `read_usd`、不写死 prim；Oracle 与未来感知走同一查询面；策略面 / 评测面不混进 B 轨。  
2. **同一 `lab ctrl-sim run` 可切换** template / oracle / 学习后端，Low 话题不变。  
3. **投影可加宽：** 增加图像或语言条件时，state 路径与 HOLD 不破。  
4. **谓词可机读** 并被 L0 挂到 run（允许第一期为运动代理，但须标明）。  
5. **正式学习产物可追溯** 到特征、processor/stats、schema、源 `run_id`。  
6. **没有**第二套实验 OS、第二套控制总线、也没有「实验室发行版 LeRobot」。

目录变多、对标仓变全、预测头变大，**都不算**做成。  
**没有可计算的 \(s\)，只有更强的 \(\pi(a\mid o)\)，也不算做成 L1。**
