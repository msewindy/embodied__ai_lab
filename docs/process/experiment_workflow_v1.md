## 一、核心约束与基线

为确保实验数据可追溯、物理过程安全可控，所有实验必须遵循以下基线（由总体方案与架构蓝图定义）：
1. **并发约束**：同一时间，场地内最多允许 **2 台** 机器人进行动态实验。
2. **安全约束**：动态实验期间，现场必须保证 **≥ 2 人** 在场（一人操作，一人手持急停）。
3. **数据约束**：所有动态实验必须生成全局唯一的 `run_id`；真机全量录制 rosbag；CTRL-SIM 默认 A 轨 `low.jsonl`（见 STRUCT / SOP）。

## 二、实验五阶段流程

### 阶段 1：申请与计划 (Plan)
- **动作**：填写实验计划书（包含目标、设备、风险等级）。
- **审批**：
  - 低风险（静态调试）：操作员自批。
  - 中/高风险（动态运动）：必须经 R3（安全负责人）确认场地与 SOP 就绪。

### 阶段 2：准备与环境检查 (Prepare)
- **动作**：
  - 检查设备在台账中是否为可用状态（非 blocked）。
  - 运行 `gen_run_id` 工具，绑定当前 Git Commit 和参数配置。
  - 执行实验前安全点检（Pre-experiment Checklist）。

### 阶段 3：执行与监控 (Execute)
- **动作**：
  - 严格按照设定的速度上限运行。
  - 操作员不得背对运行中的设备。
  - 若触发 Safety 模块的软停，或拍下物理急停，实验立即标记为 `interrupted`。

### 阶段 4：复盘与记录 (Review)
- **动作**：
  - 成功实验：记录结果指标。
  - 失败/中断实验：**24小时内**必须记录 Root Cause，并在周五例会复盘。

### 阶段 5：数据归档 (Archive)
- **动作**：
  - 确保 `run_id` 对应的 rosbag、日志、metadata.json 完整存入服务器。
  - 严禁删除原始 rosbag（除非 R1 批准的冷数据清理）。
