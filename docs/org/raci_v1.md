## 一、角色定义与核心职责

| 代号 | 角色 | 姓名 | 核心职责 |
|------|------|------|----------|
| **P1** | 系统/规划负责人 | P1 | 总体方案、系统架构与数据流契约、制度审批、框架阶段 Go 签字 |
| **P2** | 平台/基础设施工程师 | 待填 | 网络与算力落地、monorepo、ROS2 接口实现、版本矩阵、CI/CD |
| **P3** | 现场/资产/安全工程师 | 待填 | 场地与安全分区、资产台账、设备点检、物理安全设施、SOP 落地 |

**协作原则：**
- P1 负责“定边界、定契约”（What & Why）；P2/P3 负责“工程实现”（How）。
- 任何越过系统架构边界（如绕过 Safety 模块）的实现，P1 有权否决。

## 二、工作域 RACI

* R = Responsible (执行), A = Accountable (审批/最终负责), C = Consulted (协商), I = Informed (知会)

| 工作域 | P1 | P2 | P3 |
|--------|----|----|-----|
| 实验室总体方案与里程碑 | **A/R** | C | C |
| 系统整体架构与数据流设计 | **A/R** | C | C |
| 16 周 WBS 与阶段 Go/No-Go | **A/R** | C | C |
| 预算与采购申请 (≤20万总盘) | **A** | R | R |
| 统一消息接口 (ROS2) 详细设计 | C | **R/A** | C |
| 网络/算力规划与落地 | C | **R/A** | I |
| 场地测量、平面布局与安全分区 | C | I | **R/A** |
| 资产台账与设备点检维护 | C | I | **R/A** |
| 实验流程与 run_id 规范 | **A** | R | R |
| 变更控制（CR）与周五评审 | **A** | R | R |
| 物理急停与安全 SOP 落地 | C | C | **R/A** |

## 三、决策权限与红线

| 决策类型 | Accountable | 规则 |
|----------|-------------|------|
| 架构契约与 NFR 变更 | P1 | 必须走 CR，评估对全局的影响 |
| 实验室构建开发总投资审批 | P1 | P2/P3 提交 BOM，P1 统筹审批（上限 20 万） |
| ROS2 接口 (Topic/Msg) 变更 | P2 | P2 提案，需确保不破坏 P1 的数据流契约 |
| 安全 SOP / 物理急停策略变更 | P3 | **三人全员**同意方可生效 |
| 单台设备 status→blocked | P3 | 发现安全隐患时，P3 有权单方面叫停设备 |
